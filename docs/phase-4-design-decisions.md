# Phase 4 design decisions (before model selection)

The primary direction is an independently implemented learned frontier-cost estimator, separating *which state to expand* from Phase 2/3's *which tactic to try*. TacticToe, ReProver, HTPS and Aesop motivate this separation; none of their source code is copied. See the pinned [related-work study](phase-4-related-work.md).

| Direction (rank) | Usefulness / published motivation | CPU / compatibility | Complexity, reproducibility, portfolio value | Decision |
|---|---|---|---|---|
| 1. Learned frontier values | policy/value separation in TacticToe/HTPS; unexplored lever in Phase 3 | small regression, native snapshots already available | low–medium; exact JSON model and decision log; strong experimental separation | primary factorial experiment |
| 2. More informative representations | goal/context/progress address Phase 3 text heuristics | pre-decision native descriptions, no added Lean calls | medium; auditable named features; train-only selection | linear versus quadratic basis |
| 3. Improved best-first / beam | heuristic scheduling and bounded memory are established search tools | straightforward deterministic queue | low; identifiable pruning decisions; useful negative controls | bounded best-first beam as secondary architecture |
| 4. Premise retrieval / generation | hammers and saturation show expressiveness can dominate scheduling | local general-purpose normalizers feasible | medium–high; changing candidates confounds primary claim | isolated generator diagnostic |
| 5. Repeated-state handling | Aesop and saturation exploit structured redundancy | full Lean elaboration constraints complicate equivalence | high for certified merging; offline grouping easy to reproduce | diagnostic only; no merges |
| 6. AND/OR / hypergraph | HTPS handles jointly necessary subgoals explicitly | shared metavariables require careful proof assembly | high; valuable future work but weak causal attribution in this small phase | defer implementation, document conditions |
| 7. MCTS | UCT/RMaxTS/HTPS balance exploration and exploitation | CPU possible but rollout/value data and action branching weak | high; a superficial UCT wrapper would not reproduce cited systems | defer, preserve meaningful beam comparison |

The scalar model predicts log(1 + observed downstream attempts) under the fixed handcrafted continuation collector. It is **not** a probability of provability, admissible A* estimate, or shortest-proof estimator. Higher predicted cost yields lower expansion priority. Verified trajectories supply regression targets; censored outcomes remain in the ledger and are excluded from point targets, with counts reported. This avoids inventing negative mathematical labels but leaves survivorship bias.

Permitted training data are only the original 48 Phase 1 development theorems and their Phase 3 continuation corpus. Whole order theorems are held aside during selection, then refit on permitted development data. Pilot tasks calibrate budgets only. All earlier held-out outcomes, including Phase 3 failures and diagnostics, are exploratory and forbidden as training/selection inputs. New final statements, protocol, candidate/trust hashes and prior research artifacts are frozen before fitting.

Primary arms: BFS; handcrafted candidates/frontier; Phase 2 candidates/handcrafted frontier; Phase 3 candidates/handcrafted frontier; handcrafted candidates/learned frontier; Phase 3 candidates/learned frontier; Phase 3 candidates/bounded learned best-first beam; native Aesop. A fixed linear state model is an additional transparent ablation if the selected model is nonlinear. Native grind is a separate local symbolic reference. Every controlled ProofLab arm has the same candidate cap, search limits, independent verification and axiom audit. Beam only changes frontier retention and is explicitly incomplete.

All scores use information already observed: goals, context, depth, ancestral structural changes and generated operation counts. Future continuation outcomes are labels offline only. Scoring never invokes Lean. State insertion scores are frozen at insertion; stable node-ID ties. Branch cost uses deterministic path transitions; global attempt count is recorded in the decision log rather than learned as a progress proxy (it depends on scheduling).

No caching or transposition pruning is justified by pretty-printed goal equality. New native expression diagnostics replay actual prefixes outside timed primary searches, retain unresolved metavariable evidence, and group without altering search. Protected generator, bridge and proof verifier remain byte-identical. Separate generator diagnostics can add general local normalization, lattice premises and rewrite alternatives, never task IDs or answer scripts.
