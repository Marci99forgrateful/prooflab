# Native retrieval and its CPU model

Phase 5 changes candidate availability. The Phase 3 outcome ranker and Phase 4 frontier model remain frozen scheduling references. `TypedProvider` produces the same typed `Candidate` objects used by earlier policies; the selected pool is subsequently ordered through the existing `RankingPolicy` interface. Candidate retrieval scores and action scheduling scores are different quantities.

## Native symbolic component

`ProofLab/Retrieval.lean` independently implements bounded queries using public Lean APIs. The unchanged `Bridge`, `LeanSession` and independent fresh-process verifier remain intact. All Phase 5 experimental arms use the same separately named retrieval-session bootstrap, mathematical imports, memory limit, tactic heartbeat limit and saved-state semantics. Original/expanded arms do not issue retrieval queries.

The public seed list requests a bounded subset of declarations already available through the Bridge imports. The native exporter records 116 existing declarations, actual types/ASTs, source modules, conclusion heads and implicit/instance/premise counts. Fifteen unavailable requested names are explicitly recorded in `declarations.json`. This is a finite reproducible index, not a whole-Mathlib search or a scalable discrimination tree. Exact native ASTs live once in the canonical index; replay rows reference its SHA-256 and retain actual instantiated proposal information.

Each query checks at most 128 declarations, up to 16 rewrite directions and a bounded witness construction budget. Fresh universe metavariables, non-reducing `forallMetaTelescope`, conclusion `isDefEq` and required instance synthesis test potential compatibility. Generic declarations such as `And.left` can unify while leaving useless `R ∧ ?b` obligations. Compatibility therefore never means an actual tactic succeeded. Required propositions and unresolved non-instance data parameters are exposed; the historical wire field `unresolved_explicit_data` counts both implicit and explicit unresolved data.

Rewrite probes use native `MVarId.rewrite` in each direction, restricted to a concrete left-hand-side head occurring in the actual target, with at most 16 direction probes. Generic metavariable-only left-hand sides do not consume this budget. Rewriting returns the actual transformed target and remaining obligations. Both metadata probes and the full query restore native state. Actual selected tactics are executed separately from the saved parent.

Existential construction reads the native expected carrier type. It retains at most twelve local data terms and six local functions, makes at most 32 typed application attempts at depth at most two, then up to 48 total construction attempts when a product carrier permits pairs of the first eight terms. Nat carriers additionally admit 0/1. `mkAppM'`/`mkAppM` check argument types and insert implicits/instances; unresolved expression metavariables are not emitted as finished application witnesses. Returned witness rows show the inferred type, expected type, compatibility and construction. No theorem ID or answer template is inspected. The function bank is fixed to original local functions: composed unary applications are supported, but constructed partial applications are not promoted to new callable functions; arbitrary curried binary applications can therefore be missed. Predicate/type-valued applications may also consume part of the finite attempt budget.

The explicit group normalizer uses associativity, identities and inverse cancellation only; no commutativity assumption is introduced for a `Group`. A bounded `simp only` set-membership proposal is distinct from it. Original `ring`/`omega` actions remain visible specialized automation. The Phase 4 expanded arm separately includes `simp_all`. Aesop and grind are single-call external references, never hidden inside a ProofLab policy.

## Fixed-cap allocation

The cap is 24. Up to sixteen original actions receive protected lanes, considering structural `goal` and `specialized` actions before other original actions, preserving their original order within these groups. Novelty fills the remaining capacity; unused original actions backfill any space. Protection is bounded: in large contexts some original actions can still be displaced. Every state records original/selected/entered/displaced actions and selection reasons.

Broad selection admits unfiltered proposals in stable index order. The filter-only control gates native proposals by compatibility without relevance ordering. Deterministic selection combines compatible witness/normalizer families, required-premise agreement, rewrite size change, unresolved parameters and repeated-target penalties. These include explicitly identified textual relevance estimates; only Lean certifies actual application. Learned retrieval uses the same universe, gate, lanes, cap and action-prior values as deterministic selection and replaces novelty ordering with a fitted score. Selection returns that novelty order to the existing stable downstream ranker, so retrieval order also breaks equal handcrafted/P3 action-score ties. This experiment therefore measures retrieval selection **and tie ordering**, not a pure availability-only intervention; post-evaluation exact-prefix comparisons report both effects. The witness and normalization ablations remove only their explicitly named novel families; original witness/normalizer actions remain.

## Actual development supervision

The frozen boundary permits 48 original development theorems. Forty-seven have an audited source demonstration and contribute preferences; one has no verified source. The collector rechecks each source proof, replays up to three source states, executes at most 36 proposals per state and explores at most three accepted successors under a fixed original-generator handcrafted continuation policy. Its separate budget is depth 6, sixteen expansions, 64 attempts, four search seconds and two seconds per tactic; complete-proof auditing has a separate twenty-second allowance.

The 99 source states yield 1359 actual applications: 211 rejected applications, 195 independently verified continuations, 851 accepted but unexplored outcomes and 102 accepted censored outcomes. No rejected training application contains a heartbeat, timeout, recursion or memory-limit error. None of the last two groups is a negative label. Rejected application means the exact elaborated tactic failed from that saved state; it does not mean a mathematical proposition is false. Source-path evidence is positive only after fresh full-proof auditing and actual action replay. All selected source actions received successful audited continuation evidence in this collection.

There are 555 pairwise preferences across 47 contributing theorems. Eighty compare genuinely completed continuations with unequal observed attempt costs; the remaining 475 compare verified-path actions against actually rejected applications. Per-state preferences receive weight `1 / number_of_state_preferences`, limiting repeated rejection dominance. Accepted/censored alternatives never appear on the losing side solely because they were not solved. This is biased finite-policy supervision rather than optimal mathematical relevance.

## Architecture, selection and reproducibility

The model is a linear CPU pairwise logistic ranker with 130 observed feature coefficients. It reuses versioned Phase 3 pre-action structural features and adds native compatibility, proposition-premise counts/agreement, unresolved parameters, missing instances, witness depth, rewrite obligations/size change, implicit/instance counts and proposal-family indicators. It receives neither theorem identifiers nor future states, rollout outcomes, audit results or proof-path labels at inference. Unseen declaration names do not create vocabulary-specific weights; the existing structural features still apply. Original declaration feature vectors are unchanged.

Zero initialization, sorted feature names, full-batch gradient descent, 250 epochs, step `0.15 / sqrt(1 + epoch/50)` and L2 candidates 0.01/0.1 are frozen. The twelve whole-order development theorems are the validation boundary: 495 selection-training pairs and sixty validation pairs. L2=0.01 gives validation pair loss 0.4047496 versus 0.4977749 for 0.1 and 0.6931472 for zero weights. This is development ranking evidence, not held-out proof-search improvement. After selection, the model refits on the permitted development corpus. A second CPU fit produced a byte-identical model artifact.

`models/phase5/retrieval.json`, `preferences.json`, `training-report.json` and the compressed development observations preserve the coefficients, labels, raw executions and audits. `collection-source.json` identifies commit `ac76c33` as the actual loaded collection implementation; the earlier collector provenance names the then-existing parent. Subsequent formatting and removal of duplicated index ASTs from replay payloads do not change features or labels. The pre-test execution freeze hashes the final scorer, search runner, index, old scheduling models and trained model. No held-out result selects a model or changes a generator.

Limitations include the small biased development corpus, sparse witness/premise coverage, generic underconstrained applications, no pretrained semantic embeddings, finite index and construction depth, and incomplete compatibility probes. A positive pair loss result cannot guarantee that the same ranker selects useful novelty on new mathematical families.

## Wire-format compatibility

The additive trace format retains older metadata. `metadata.generator` names the fallback callback argument; the provider overrides it in Phase 5. Actual generation is identified by `metadata.arm`, `generator_mode` and each query's `mode`. Likewise, `metadata.model_sha256` and `learned_scores_used_for_scheduling` refer to the Phase 2 comparison scorer; the new retrieval model is identified by query-level `model_sha256` and the Phase 5 execution freeze. The Phase 4 value model may be an annotation unless the actual algorithm uses it. `metadata-notes.json` records these scopes without rewriting the raw execution evidence.
