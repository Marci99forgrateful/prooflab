# Phase 6 local models and learning objective

ProofLab uses two separate CPU models: a candidate-usefulness ranker chooses hybrid novelty, and a mathematical-context cost selector chooses symbolic, hybrid or typed generation. The selected artifact contains 130 relevance coefficients and 48 depth-two controller trees (75,257 JSON bytes including provenance). The fully linear reference has 108 controller coefficients. Final action execution uses the unchanged Phase 3 scorer with an explicit tactic-string tie rule. Neither new model certifies a tactic or a proof.

## Candidate usefulness

The input combines frozen operation/context features with genuine native compatibility, required premises, unresolved explicit data/instances, premise coverage, rewrite obligations/direction, typed construction depth, candidate family, expanded-baseline membership, strong simplifier/group-normalizer indicators and native-context structure indicators. No theorem ID, saved-state ID, answer, future success or successor-state feature enters inference. Native probes and construction consume the measured query budget. Compatibility remains separate from actual acceptance.

A preference is positive only for a verified source/continuation action over an **actually rejected application**, or for a strictly lower attempt count among **two independently verified fixed-policy completions**. Each source state's preferences have total weight one. Unknown/censored branches are retained without usefulness-negative labels. Observed goal changes, unresolved obligations and branching remain outcome diagnostics; they are not privileged pre-action inputs.

The transparent linear baseline minimizes pairwise logistic loss with L2 regularization, using 200 deterministic full-batch steps, initial zero weights and rate `0.15 / sqrt(1 + epoch/50)`. L2 candidates are 0.01 and 0.1. State-only terms cancel in a within-state linear pair; useful context dependence therefore comes from the predeclared operation/context features and specialized family indicators. The model is not an unrestricted mathematical representation learner.

An independently implemented tabular booster fits pairwise-logistic pseudo-responses with weighted histogram-CART regression trees. The grid is depth one/two, 24/48 iterations, rate 0.1, minimum twelve distinct feature-vector rows per leaf and approximately 85% feature subsampling. Splits inspect up to seven quantiles (all values when small). Zero-gain intermediate splits allow depth-two interactions; constant pseudo-responses stop. Seeds 0/1/2 are fixed, and the mean whole-family validation loss selects the configuration. This is a small first-order booster, not an optimized XGBoost/LightGBM implementation; the finite grid does not establish general inferiority of nonlinear learning.

On 120 training / forty whole-family validation tasks, linear L2=0.01 gives **0.460912** validation logistic loss. L2=0.1 gives 0.530449; the best boosted grid cell (depth two,48 trees) averages **0.527345** across seeds. The zero scorer gives 0.693147. The selected relevance remains linear. The rejected seed-zero boosted validation expert is exported for inspection and is not a final-test search policy.

The selected relevance expert retains its **120-task training fit**. Refitting it on validation-family action labels before collecting controller-validation costs would contaminate that procedure. An initial unused full refit is archived, with the correction registered before controller collection/selection and before any final test.

## Adaptive conditional-cost controller

From each development root, three genuine fixed-mode runs use the same fitted relevance component, canonical shared-Candidate metadata/P3 ties, native environment and resource budget. A target is `log(1 + actual candidate attempts)` **conditional on independent proof verification**. Of 480 runs, 347 provide targets; other runs remain archived with their actual termination, not labelled mathematically impossible.

Pre-decision inputs include native typeclass/goal heads, quantified/existential structure, context/function/equality counts, visible set/inverse/product structure, goal size/count and explicit context-by-mode features. Ridge regression competes with 48 depth-two boosted squared-residual trees. The predefined whole-family validation MSE selects the architecture. Linear gives **1.229892** and boosted seed zero **1.202460**. This small validation difference selects the boosted controller under the registered rule; it is not itself evidence of better unseen proof search. The selected controller refits all 347 permitted development costs. Primary seed zero remains fixed; controller seeds one/two are separate preregistered final sensitivity arms, with identical relevance weights.

At an expanded state, the controller evaluates all three mode costs and chooses the smallest, with deterministic mode-name ties. Hybrid mode uses fitted candidate relevance for novelty selection. Typed mode uses its recorded deterministic typed selection. Symbolic mode performs no native retrieval. Every executed score, mode, selection/displacement and actual tactic outcome is retained.

## Controls and limits

The **fully linear adaptive control** uses the same linear relevance expert and a ridge cost controller on identical development data. The applicability-only control changes relevance supervision while holding the selected boosted controller fixed. Deterministic context-aware and staged policies use no learned mode selector. These controls distinguish learning from native expression availability, symbolic automation and quota allocation; no gain is attributed automatically to ML.

Conditional-cost learning has important limits: failed/censored modes contribute no regression target, so missingness depends on success; root-only costs do not teach arbitrary intermediate-state behavior; fixed-mode continuation costs are approximate surrogates for greedy switching; and training uses eight seconds/160 attempts while final budgets are larger. The matched collection compares all modes under one pinned source version (`689ea1d`); later pre-test native deduplication/bound guards and instrumentation are source-version shifts, not retroactively remeasured collection targets. The selector predicts neither provability nor calibrated success probability and can choose an unsuccessful expert. Attempt targets also omit primitive-inference equivalence and do not directly optimize wall/CPU overhead. Those costs and any regressions are measured separately.

Models are standard JSON with exact coefficients/trees, features, data/source hashes and boundaries in [models/phase6](../models/phase6). Inference uses Python scalar arithmetic; NumPy is training-only. Actual final parameter refitting used one CPU thread, about **18.76 seconds wall /18.95 seconds user+system CPU**, with a **510156 KiB** trainer-process high-water RSS bound. Lean data-generation costs are separate and much larger; aggregate campaign CPU is not fully instrumented. No pretrained weights, hosted inference, paid AI APIs or GPU are used.
