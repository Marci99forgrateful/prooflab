# Why Phase 5 needs an adaptive architecture

This diagnosis uses the preserved Phase 4/5 source and experiments only. It motivated development; it is neither Phase 6 training data nor fresh evaluation evidence. The machine-readable [diagnosis record](../research/phase6/diagnosis.json) pins eight source locations to Phase 5 commit `4cc061e`, twelve historical traces with their hashes, observations and causal hypotheses. The original [Phase 5 analysis](phase-5-results.md) remains unchanged.

| Failure mechanism | Actual historical evidence | Phase 6 intervention and limit |
|---|---|---|
| Protecting the weaker generator | On Phase 5's forty statements, expanded P4/P3 verifies 29, while typed/P3 verifies 15. `TypedProvider` protects original structural proposals rather than the expanded set containing `simp_all`. | Start from the strongest expanded generator; record which baseline actions survive each allocation. Global budget protection is not a theorem-success guarantee. |
| Missing useful normalizer supervision | On `p5_conjugate_context`, after `rw [← h]`, learned retrieval replaces a group normalizer with `Or.elim`; the two recorded runs grow from 157 to 485 attempts. Old training lacks Group/Lattice contexts. | Add genuine group/lattice development data, strong-normalizer and context features; compare usefulness with applicability-only supervision. A generic rule is not declared mathematically false. |
| Hidden action-order changes | 2736 of 2738 matched Phase 5 prefixes have identical pools but changed execution order without changed shared P3 scores. Stable ranking inherits learned retrieval order. | Canonicalize shared Candidate metadata and score/tactic-string ties in new modes. Keep a separate P4 canonical-tie control; historical methods retain their own semantics. |
| Valid but unproductive branches | In the historical `p4_cubic_pair` coverage study, original search verifies at 386 attempts; expanded and typed searches exhaust 600 although root proof actions remain available. | Retain actual branch outcomes, attempts and continuation costs. Distinguish displacement from additional branching; an accepted application is not verified usefulness. |
| Typed capability cannot replace symbolic automation | `p4_inverse_right` takes two attempts with expanded `simp_all`, versus 22 typed attempts; `p4_lattice_meet` verifies in thirteen expanded attempts but typed exhausts 600. | Explicit structure-aware symbolic/hybrid/typed choice, protected specialized actions and bounded novelty. The learned selector must earn its comparison against expanded P4. |
| Missing expressions | `p4_witness_transport` exhausts original/expanded search in six/seven attempts; typed verifies `exists (f a); apply h; assumption` in 37. Phase 5 only iterates original local functions, so generated partial applications cannot become new callables. | Bounded native callable closure, products and typed context subterms. Inspect construction depth/type; incomplete synthesis remains a source of unsolved tasks. |
| Resource censoring and missing instrumentation | Phase 5 records nine Lean interaction timeouts as well as attempt/expansion/depth limits. A failed native query can return no native counters. | Meter every attempted query and its elapsed wait; preserve returned native error counters and leave missing counters unknown. Finite exhaustion is not mathematical impossibility. |

The cap of 24 can remove a proof-path action, but the existence of a regression alone does not identify displacement as its cause. Exact-prefix availability, selected membership, action scores/order and actual attempted children must be inspected together. Candidate protection and stronger automation can help without machine learning; the final experiment separately measures those effects.

The new hybrid therefore uses reservations and explicit eligibility rather than concatenating and truncating. Normally four slots are reserved for typed novelty, eight for existential goals, with unused baseline capacity available for eligible novelty. Symbolic capabilities and novelty share a single fixed global search budget. See the [architecture](phase-6-architecture.md) and the post-evaluation [error analysis](phase-6-error-analysis.md) for what these changes actually achieve.
